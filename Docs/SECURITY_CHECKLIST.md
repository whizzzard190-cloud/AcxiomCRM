# AcxiomCRM - Security Checklist & Hardening Verification

This document details all security controls implemented in AcxiomCRM, corresponding configuration settings, verification mechanisms, and test evidence.

| # | Security Control | Implementation Details | Configuration / Code Location | Verification / Test |
|---|---|---|---|---|
| 1 | **Password Hashing** | PBKDF2 with HMAC-SHA256 via ASP.NET Core Identity. No custom password tables. Salted and hashed automatically. | `Program.cs` Identity Configuration | Verified via Identity integration & `DbInitializer`. |
| 2 | **Password Policy** | Minimum 8 characters, at least 1 digit, 1 uppercase, 1 lowercase, 1 non-alphanumeric special character. | `Program.cs` (`options.Password.*`) | **Golden Test G033** verifies weak password rejection. |
| 3 | **Account Lockout Protection** | Automatic account lockout after 5 consecutive failed login attempts for 15 minutes. | `Program.cs` (`options.Lockout.*`), `AccountController.Login` | **Golden Test G018** verifies lockout enforcement; **G036** verifies admin unlock. |
| 4 | **Role-Based Access Control (RBAC)** | Roles: `Admin`, `Manager`, `SalesExecutive`. Centralized policy enforcement across controllers. | `Authorization/ResourceAuthorizationService.cs` | Verified via controller `[Authorize(Roles = ...)]` attributes and service methods. |
| 5 | **Resource & Scope Authorization** | SalesExecutives access only their own records (`OwnerId` / `AssignedTo`). Managers access their direct reports' records + their own. Admins have global access. | `IResourceAuthorizationService.cs`, `CustomerService`, `OpportunityService`, etc. | **Golden Tests G014, G015, G037** verify server-side denial for out-of-scope access. |
| 6 | **Cross-Site Request Forgery (CSRF)** | `[ValidateAntiForgeryToken]` enforced on all state-changing MVC POST endpoints. Cookie configured with `SameSite=Strict`, `HttpOnly=true`, and `SecurePolicy=Always`. | `Program.cs` (`builder.Services.AddAntiforgery`), all MVC Controllers | **Golden Test G034** verifies reflection check on all POST actions. |
| 7 | **SQL Injection Prevention** | 100% EF Core parameterized LINQ queries. Zero raw string concatenation, zero `FromSqlRaw` or dynamic SQL. | `ApplicationDbContext.cs`, all Service implementations | **Golden Test G035** passes SQL injection payloads (`' OR '1'='1' --`) with safe zero matches. |
| 8 | **Cookie Hardening** | Authentication and Anti-Forgery cookies configured with `HttpOnly = true`, `SameSite = SameSiteMode.Strict`, `SecurePolicy = CookieSecurePolicy.Always`. | `Program.cs` (`ConfigureApplicationCookie`, `AddAntiforgery`) | Code inspection and browser HTTP headers. |
| 9 | **HTTPS Redirection & HSTS** | Strict HTTPS redirection enabled; HTTP Strict Transport Security (HSTS) configured with 1-year max age, subdomains, and preloading. | `Program.cs` (`UseHttpsRedirection`, `UseHsts`, `AddHsts`) | HTTP pipeline configuration verified. |
| 10 | **Security Response Headers** | Middleware attaches OWASP-recommended headers: `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`. | `Program.cs` (inline security headers middleware) | HTTP response headers inspection. |
| 11 | **REST API DTO Isolation** | EF Core database entities are never exposed across API boundaries. Strict request/response DTOs prevent mass assignment and over-posting. | `DTOs/ApiDtos.cs`, `Controllers/Api/*` | **Golden Test G019** confirms no passwords or sensitive fields exist in DTOs. |
| 12 | **Rate Limiting** | Built-in ASP.NET Core FixedWindow rate limiter applied to `/api/auth/*` endpoints (5 requests per minute). | `Program.cs` (`AddRateLimiter`, `UseRateLimiter`), `AuthController.cs` | Rate limit middleware active on Auth routes. |
| 13 | **Secret Management** | Connection strings and seed passwords read from `appsettings.json`, environment variables, or `dotnet user-secrets`. Never hard-coded. | `Program.cs`, `Data/DbInitializer.cs` | Clean repository check: zero hard-coded credentials. |
| 14 | **Sensitive Data Redaction** | `AuditService` recursively sanitizes JSON payloads, stripping `Password`, `PasswordHash`, `Token`, `Secret`, etc. | `Services/AuditService.cs` (`SanitizeAndSerialize`) | **Golden Test G020** confirms complete stripping of sensitive properties. |
| 15 | **Immutable Audit Log** | Audit log repository is strictly append-only. No update or delete endpoints exist in code or API. | `Services/IAuditService.cs`, `AuditLogsController.cs` | **Golden Test G042** confirms zero delete/update methods on `IAuditService`. |
| 16 | **Safe Error Responses** | Zero technical stack traces, connection strings, or internal exceptions exposed to clients; standard RFC 7807 `ProblemDetails` used for API errors. | `Controllers/Api/*`, `HomeController.Error` | Error handling verified across API endpoints. |
